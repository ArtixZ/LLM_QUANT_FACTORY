# Factor Homogeneity Control

AutoAlpha should not reward a model for repeatedly rediscovering the same
price-volume effect with a different window, rank transform, or sign convention.
The production research loop therefore treats factor novelty as a first-class
admission gate, not only a UI diagnostic.

## Protocol

`A_SHARE_FACTOR_HOMOGENEITY_CONTROL_V1`

The protocol consumes the full-library behavior snapshot generated by
`A_SHARE_FACTOR_BEHAVIOR_CLUSTER_V1` and creates two outputs:

- A research-program directive for the LLM before proposal generation.
- Candidate-level homogeneity metrics after deterministic evaluation.

## Research-Time Controls

Each AutoAlpha iteration now injects `homogeneity_control` into both
`research_program` and `data_context`.

The directive contains:

- `must_avoid_cluster_ids`: crowded behavior clusters that should be folded to
  their leader instead of mutated again.
- `preferred_mechanisms`: sparse mechanisms with fewer behavior clusters.
- `discouraged_mechanisms`: mechanisms where many candidates collapse into few
  behavior clusters.
- `primary_rule`: the model must open a new behavior cluster or sparse
  mechanism; parameter-only variants are not acceptable research progress.

This makes the generation prompt aware of the current library topology before it
submits another factor.

## Admission-Time Controls

After the candidate is evaluated, AutoAlpha computes:

- `homogeneity_gate_passed`
- `homogeneity_gate_failure`
- `homogeneity_novelty_score`
- `homogeneity_cluster_id`
- `homogeneity_cluster_size`
- `homogeneity_nearest_factor_id`
- `homogeneity_nearest_similarity`
- `homogeneity_redundancy_label`

The candidate is blocked from `ELIGIBLE` admission when it is a near duplicate or
a substitute inside a crowded behavior cluster. It may still be persisted as an
observed factor, preserving audit evidence without letting clones dominate
subsequent AutoCombine or QuantCombine searches.

Exceptional candidates can still pass if their long-only evidence exceeds the
existing redundancy override threshold, but the burden shifts to performance and
stability, not cosmetic formula variation.

## Library Controls

The factor library API exposes:

- `homogeneity_control`
- `summary.crowded_behavior_cluster_count`
- `summary.homogeneity_target_mechanisms`

The factor page also shows crowded behavior clusters and candidate-level
homogeneity metrics in each factor detail panel.

## Design Intent

The system should prefer:

- New behavior clusters over larger same-cluster member counts.
- Mechanism diversity over repeated liquidity or reversal variants.
- Cluster leaders over same-cluster followers.
- Portfolio marginal contribution over standalone factor score.

The objective is not to delete similar factors. The objective is to keep them as
evidence while preventing them from consuming the scarce eligible factor and
combination-search budgets.
